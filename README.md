# 호스피스간호실무 진단·형성평가 앱

2026-2 호스피스간호실무(간호학과 4학년) 진단평가 1회와 1~14주차 형성평가를 위한 웹 앱입니다.

- 학생은 휴대폰이나 PC에서 문제를 풀고 **결과 제출**을 누릅니다.
- 결과는 교수님의 구글 스프레드시트에 쌓입니다.
- 교수님은 `admin.html`에서 출석부, 평가 결과, 성적 산출 자료, 활동 기록을 확인합니다.

| 파일 | 역할 |
|---|---|
| `index.html` | 학생용 페이지 (진단평가 20문항, 1주차 3문항, 2~14주차 각 5문항) |
| `admin.html` | 교수용 결과 확인 (전체 현황, 평가별 결과, 문항 분석, 학생별 성적표, CSV 내려받기) |
| `questions.js` | 문항은행. 문항을 고치려면 이 파일만 수정합니다 |
| `config.js` | 서버 주소(API_URL)와 과목 표시 이름 |
| `apps-script/Code.gs` | 결과를 저장하는 구글 Apps Script 서버 코드 |

---

## 2판에서 달라진 점

- **로그인 기록:** 학번과 이름으로 들어온 시각이 남습니다. `students` 탭에 명단을 넣으면 명단에 있는 학생만 들어올 수 있습니다.
- **'강의를 들었습니다' 체크:** 강의 코드 없이 체크만 하면 바로 평가로 넘어갑니다. 체크한 시각이 기록됩니다.
- **자동 제출:** 마지막 문항을 풀면 버튼을 누르지 않아도 바로 제출됩니다. 인터넷이 끊겨도 휴대폰에 저장했다가 다음에 앱을 열 때 자동으로 다시 보냅니다.
- **풀이 기록:** 평가마다 다음 내용이 남습니다.
  - 시작 시각과 제출 시각
  - 전체 소요 시간과 문항별 풀이 시간
  - 풀이 중 다른 화면으로 나간 횟수
  - 응시 회차와 기기(휴대폰/PC)
- **교수용 화면:**
  - 출석부: ○ 출석, △ 지각, · 미제출
  - 평가별 결과: 너무 빨리 풀었거나 화면을 자주 나간 제출에 ⚠ 표시
  - 문항 분석
  - 성적 산출: 출석·지각·결석 횟수와 형성평가 평균
  - 활동 기록
  - 각 화면은 CSV로 내려받을 수 있습니다.
- **마감 시각:** `config.js`의 `DEADLINES`에 주차별 마감을 넣으면, 마감 뒤 제출은 지각으로 표시됩니다.

> **알아 둘 점:** 이 앱은 영상을 실제로 끝까지 봤는지는 알 수 없습니다. 영상이 LMS 밖에 있기 때문입니다. '강의 들음 체크 시각'과 '풀이 기록'을 LMS의 영상 진도율과 함께 보시면 가장 정확합니다.

## 1단계. 구글 시트와 서버 만들기 (처음 한 번)

1. 구글 드라이브에서 새 스프레드시트를 만들고 **확장 프로그램 → Apps Script**를 엽니다.
2. 기본 코드를 지우고 `apps-script/Code.gs` 전체를 붙여 넣습니다.
3. 맨 위 `ADMIN_PASSWORD`를 교수님 비밀번호로 바꾸고 저장합니다.
4. 함수 선택 칸에서 `setup`을 고르고 **실행**합니다.
   - 권한 요청이 뜨면 허용합니다. "확인되지 않은 앱"이 나오면 **고급 → 이동**을 누릅니다.
   - `submissions`, `log`, `students` 탭이 생깁니다.
5. **배포 → 새 배포 → 유형: 웹 앱**을 선택합니다.
   - 실행 사용자: **나**
   - 액세스 권한: **모든 사용자** ('Google 계정이 있는 모든 사용자'를 고르면 학생 제출이 실패합니다)
   - **배포**를 누릅니다.
6. 나온 주소(`https://script.google.com/macros/s/…/exec`)를 복사합니다.
7. (선택) `students` 탭 A열에 학번, B열에 이름을 붙여 넣으면 명단에 있는 학생만 로그인할 수 있습니다.

### 이미 1판을 설치했다면 (업데이트)
1. Apps Script의 코드를 새 `Code.gs`로 **전부 바꿔** 붙여 넣고 저장합니다.
2. `setup`을 **다시 실행**합니다.
3. **배포 → 배포 관리 → 연필 아이콘 → 버전: 새 버전 → 배포**를 누릅니다. 이렇게 해야 바뀐 코드가 반영되고, 주소는 그대로 유지됩니다.
4. 예전 `responses` 탭의 기록은 그대로 남아 있지만, 새 화면에는 `submissions` 탭의 기록만 나타납니다.

## 2단계. config.js 수정

깃허브에서 `config.js`를 열고 **연필 아이콘**을 누릅니다.

```js
const API_URL = "https://script.google.com/macros/s/여기에-복사한-주소/exec";
const DEADLINES = { dx: "2026-09-07T23:59", w1: "2026-09-07T23:59", w2: "2026-09-14T23:59", ... };
```

마감을 쓰지 않으려면 `DEADLINES`는 비워 두어도 됩니다. 수정이 끝나면 **Commit changes**를 누릅니다.

## 3단계. 깃허브에 올리기

저장소에서 **Add file → Upload files**를 누르고, 새 파일들을 끌어다 놓아 **덮어씁니다.**
- 대상: `index.html`, `admin.html`, `style.css`, `config.js`, `questions.js`, `README.md`, `apps-script/Code.gs`
- config.js에 넣어 둔 주소가 덮어써지지 않도록, **config.js는 올리기 전에 주소를 먼저 넣어 두거나 업로드 목록에서 빼세요.**

1~2분 뒤 학생은 `https://아이디.github.io/hospice-eval/`, 교수님은 `…/admin.html`을 엽니다.

## "채점(제출)이 안 돼요" 점검 순서

교수용 화면 로그인 창의 **서버 연결 점검** 버튼을 누르면 원인을 알려 줍니다. 직접 확인하려면 아래 순서로 보세요.

1. **API_URL 확인:** `config.js`의 `API_URL`이 비어 있지 않고 **`/exec`로 끝나는지** 확인합니다. `/dev`로 끝나는 주소는 안 됩니다.
2. **주소 직접 열기:** 그 주소를 브라우저 주소창에 붙여 넣었을 때 `{"ok":true,"service":"hospice-eval","version":2,...}`가 보이면 서버는 정상입니다.
   - 로그인 화면이나 오류가 나오면 배포의 **액세스 권한이 '모든 사용자'인지** 확인합니다.
3. **새 버전 배포:** Code.gs를 고친 뒤 **새 버전으로 배포했는지** 확인합니다.
4. **새로고침:** 학생 휴대폰에 예전 화면이 남아 있으면 새로고침하거나 브라우저를 닫았다 엽니다. 카카오톡 안에서 열었다면 **다른 브라우저로 열기**를 권합니다.
5. **보내지 못한 기록:** 학생 화면에 "보내지 못한 기록"이 보이면, 연결된 뒤 **다시 보내기**를 누르거나 앱을 다시 열면 자동으로 전송됩니다.

## 문항 고치기

`questions.js`에서 문항을 고칩니다.
- `q`: 문제
- `o`: 보기 4개
- `a`: 정답 번호. **0부터 셉니다.** 1번 보기가 정답이면 0입니다.
- `e`: 해설

교수용 화면은 제출된 응답을 문항은행으로 다시 채점합니다.

## 알아 둘 점

- **학생 본인 인증:** 비밀번호가 없어 다른 사람이 학번을 입력할 가능성은 남아 있습니다. 명단 등록과 활동 기록(기기, 시각)으로 이상한 제출을 확인할 수 있습니다.
- **교수 비밀번호:** Apps Script 서버에만 저장되고 깃허브에는 올라가지 않습니다.
- **정답 공개:** 학생 화면에 정답과 해설이 나오는 형성평가용 앱입니다. 성적용 시험에는 쓰지 마세요.
